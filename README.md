# IBSolver

Етап 1: настільний застосунок для Windows 10/11 на Go, Wails v2 та SQLite.
Український інтерфейс, темна тема, кілька конфігурацій і Canvas-графік до шести
часових рядів. Спеціалізованого чисельного ядра поки немає.

## Запуск

Потрібні Go 1.27.1+, Wails CLI 2.16.0, Node.js/npm та WebView2. Наявне середовище
перевіряється командою `wails doctor`. Початковий каркас створено офіційною
командою `wails init -n IBSolver -t vanilla`.

```powershell
cd D:\go\ibsolver
wails dev
```

Збірка: `wails build -trimpath`; готовий застосунок — `build\bin\IBSolver.exe`.
Для відтворюваного встановлення frontend-залежностей: `cd frontend; npm ci`.
Якщо sandbox не дозволяє запис у стандартні кеші, перед командами встановіть
`$env:GOCACHE="$PWD\.cache\go-build"` та
`$env:npm_config_cache="$PWD\.cache\npm"` з кореня репозиторію.

## Робота і збереження

- Нова конфігурація створюється кнопкою «Нова». Валідні зміни назви та чотирьох
  демонстраційних параметрів автоматично записуються під час введення. Кнопка
  «Зберегти» явно підтверджує запис. Дочекайтеся позначки «Збережено» перед закриттям.
  Незавершені або некоректні значення не замінюють останні збережені параметри.
- «Створити DEMO» генерує шість математичних рядів, зберігає їх транзакційно й
  лише після успішного запису показує новий результат. DEMO не є фізичним розрахунком.
  «Розрахувати» неактивна до реалізації чисельного ядра.
- Перемикання конфігурацій і повторний запуск відновлюють збережені числові дані
  без генерації рядів. Зміна параметрів залишає попередні результати та позначає їх.
- Легенда керує видимістю кривих. Нормалізація кожної кривої: `y / max(abs(y))`;
  окремий множник 0,1…10 змінює відображення. Курсор показує вихідні значення
  найближчої спільної часової точки. Для масштабу понад 1 крива обрізається межею області.
- Ширина результатів змінюється перетягуванням роздільника або стрілками клавіатури,
  коли роздільник у фокусі. Видимість, масштаби та ширина зберігаються глобально.
- «Відновити з БД» повторно завантажує робочий стан. Пошкоджений або несумісний
  результат пропускається з повідомленням; параметри залишаються доступними.

База: `%APPDATA%\IBSolver\ibsolver.db` (`os.UserConfigDir`). Міграція v1 використовує
`PRAGMA user_version`; новіші невідомі схеми відхиляються без зміни. Таблиці:
`configurations`, `runs`, `run_series`, `app_settings`. Ряди — один gzip JSON BLOB
на запуск; параметри конфігурації та незмінний знімок запуску зберігаються окремо.
База, кеші, залежності та результати збірки виключені з Git.

## Структура і залежності

- `internal/domain`: типи й перевірки без Wails/SQLite.
- `internal/application`: координація сценаріїв і послідовність записів.
- `internal/storage/sqlite`: параметризований SQL, міграція, транзакції, відновлення.
- `internal/chartdata`: явна DEMO-генерація без предметної фізики.
- `app.go`: тонкий Wails API; `frontend/src/chart.js`: незалежний Canvas-компонент.
- Wails v2 — настільне вікно й Go/JS bridge; `modernc.org/sqlite` — SQLite без CGO;
  Vite — стандартний toolchain офіційного Vanilla JS шаблону. UI/chart frameworks та ORM відсутні.

Workspace: `D:\go\ibsolver.code-workspace` містить Source і References.
`D:\go\ibsolver-refs` використовується лише для читання і не є репозиторієм.
Перелік джерел — [docs/SOURCES.md](docs/SOURCES.md).

## Перевірка

`go test ./...` перевіряє SQLite-міграцію, перезапуск, незмінність знімків і точне
відновлення рядів, налаштування, пошкоджені результати та відкат невдалого запису.
Frontend: `npm run build` у `frontend` (після генерації bindings командою Wails).
Повна desktop-збірка: `wails build -trimpath`.

Для Stage 1 також виконано native smoke у власному тестовому профілі: DEMO,
автозбереження, курсор, масштаби та відновлення після перезапуску з незмінною
контрольною сумою рядів. Перевірено native-розміри вікна 800×560 і 1280×800.
Для автоматизації використано окрему діагностичну збірку з локальним портом
WebView2; робочий `IBSolver.exe` його не відкриває.

Наступний етап — узгодження параметрів та одиниць за оригінальними BAS/XLS,
після чого окреме чисельне ядро з відтворюваними перевірками. У Stage 1 формули
історичної програми не досліджувалися й не переносилися.
